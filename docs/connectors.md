# Packaged connectors

Connector routes use `/api/v1/connectors/sources/{source_id}`. The owner creates a source and configures it with `PUT /configuration`, then issues a source-scoped collector token through `POST /api/v1/ingestion/sources/{source_id}/collector-credential`. Keep that token in an n8n Header Auth credential; do not put provider secrets in BBD-OS source configuration. Collector access is revoked automatically when the source is paused or archived.

Configure RSS/Atom sources with `{"feed_url":"https://example.org/feed.xml"}`, web sources with `{"url":"https://example.org/","js_render":false}`, and REST sources with a URL plus `items_path`, `id_field`, `title_field`, `content_field`, and optional `updated_field`. Configuration rejects unknown fields, non-public hosts and invalid IANA timezones. New and unconfigured sources use `Asia/Ho_Chi_Minh`. RSS/Atom reads at most 10 pages, catches up from the last accepted cursor with a one-day overlap, caps aggregate response data at 25 MiB, and fetches through the isolated browser service with its shared 60-second job limit. Provider credentials belong in n8n credentials.

Import the inactive workflow exports from `infrastructure/n8n/workflows/`. Connector setup in Sources creates an RSS, web, or REST source, validates it, then shows a one-time collector token. Set `BBD_SOURCE_ID` in the local environment and n8n container to that source ID, map the imported “BBD-OS source collector” reference to the token, configure the REST credential reference when using REST, set the workflow timezone to match the source, then activate the workflow. Configure the “BBD-OS manual trigger” Header Auth credential with header `X-BBD-Webhook-Token` and the same local `N8N_WEBHOOK_TOKEN` used by the API. The manual webhook path is type-specific and remains private to the connectors network; the owner UI invokes the API's authenticated `/collect` endpoint, which returns a durable ingestion run ID. If no workflow is active or the shared token is missing, Sync now reports an error instead of pretending to collect.

REST next-page URLs must remain on the configured origin; redirects are disabled. Missing or invalid REST update timestamps use a stable observation time and leave the cursor unchanged, so unchanged pages reuse the same batch identity. Runs coalesce missed ticks by reading from the last accepted cursor. The n8n source collector credential is scoped to the configured active source. n8n schedules and provider credentials remain the connector boundary.

Run `docker compose -f docker-compose.yml -f docker-compose.connectors.yml up -d --build`. The API and worker reach the browser sidecar over a private connector network. n8n has a separate private network to the API and does not join the PostgreSQL/Redis network; its container firewall permits API traffic and DNS plus public HTTP(S), and blocks private/reserved destinations. Set `BROWSER_SHARED_TOKEN` to the same random value for the API and browser container. The browser service accepts only authenticated API requests, allows one active job, and uses a byte-counted streaming HTTP collector with BeautifulSoup by default or Playwright when `js_render` is enabled. Defaults and hard maxima are 10 pages, depth 2, 60 seconds, and 25 MiB per job. URLs, DNS answers, redirects and browser subresources are checked; the browser container firewall denies private/reserved egress and permits public HTTP(S) plus DNS. Collection never performs model-driven navigation.

URL crawl submissions return a durable `run_id` after enqueueing through the ingestion outbox; poll owner-authenticated `GET /api/v1/ingestion/runs/{run_id}` for status. The worker advances the source cursor only after browser collection succeeds. Pause and resume a source through the existing owner-authenticated `PATCH /api/v1/sources/{source_id}` status field. Paused/archived sources cannot validate, submit batches or crawl. Workflow exports are templates: imported credential references must be mapped in the local n8n instance before activation.
