# R05 — Direct OmniRoute setup and AI settings

## Implementation scope

- Reuses the existing OpenAI SDK gateway, global two-slot Redis lease, request policy, bounded retry budget, model/version contracts and typed streaming.
- Owns persisted endpoint/provider settings, encrypted credentials, aliases, chat/brief selections, timeout and separate consent grants in one PostgreSQL row with revision compare-and-swap. Browser DTOs exclude plaintext credentials.
- Keeps discovery and draft capability probes transient. Capability evidence is bound to gateway identity, model/version and capability; search generations pin gateway identity separately from provider model identity.
- Routes saved probes, hybrid embeddings, reindex selection and indexing through the settings public DTO. Search retains lexical results when encrypted semantic configuration is unavailable. Each retry send reloads and checks saved configuration immediately before transport.
- Provides /settings/ai and redirects old Models/Privacy URLs. The R05 Alembic migration depends on r03_connector_provisioning; that prerequisite still requires cross-worktree integration confirmation.

## Review repair evidence

1. **AI settings ORM model:** Added AISettingsRecord to modules/settings/models.py with fields and constraints matching r05_ai_settings.py; Alembic imports it into Base.metadata.
2. **Endpoint policy and redirects:** Added exact host/port deployment allowlist AI_ALLOWED_ENDPOINT_HOSTS (empty by default; private/self-hosted endpoints must be explicitly listed), validates saved and draft OmniRoute/web-search URLs, rejects URL credentials/query/fragment, and disables HTTP redirects on all SDK clients. Redirect responses fail at the original endpoint and are never followed with source bodies.
3. **Retry-time policy:** Moved before_send inside each retry attempt for non-streaming and streaming sends. Discovery has one send and validates immediately before it.
4. **Unsaved draft validation:** Discovery and synthetic capability probes accept an allowlisted draft endpoint before Save and require a credential reentered for that destination. They do not read/save draft settings or publish capability evidence. Draft probe response revision is 0.
5. **Independent grants:** The UI merges each edited consent flag into the existing privacy object; server-side endpoint-change resets remain in place.
6. **Lexical fallback:** Hybrid search converts settings decryption/unavailability 503 to its existing semantic-unavailable warning; other HTTP authorization/status errors still propagate. An unavailable unrelated web-search key no longer blocks embedding settings reads.
7. **Payload-safe SDK logs:** The shared gateway sets the OpenAI logger to WARNING before SDK use, suppressing DEBUG request-option/body dumps even when OPENAI_LOG=debug is configured.
8. **Capability refresh:** Saved capability evidence renders from refreshed server query data, independent of retained form drafts.
9. **Draft lifecycle:** Added saved/dirty/in-flight status, Cancel changes, disabled editing while Save is pending, and guards for browser unload and same-origin link navigation. Failed-save drafts remain in place.
10. **shadcn controls and label:** Added consumed Radix-backed Select/Checkbox primitives using semantic tokens and replaced native form selectors/checkboxes. The visible group label is canonical “AI & Ommi Router.” English form strings are handed to R09 for catalog integration; shell/theme/localization remain outside this repair.
