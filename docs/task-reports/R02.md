# R02 — Google sign-in and secure owner linking

**Status:** Production code implemented, full repository build passed, and both scoped Sol fix-round reviews approved. Runtime/provider acceptance remains deferred. No live Google credentials are configured.

## Delivered

- Added optional Google OIDC login and account link/unlink endpoints. Google login resolves only the pre-linked issuer + subject identity; it cannot create an owner or link by email.
- Authlib 1.8.0 performs provider discovery, authorization-code exchange, PKCE, nonce, JWKS signature, issuer, audience, and expiry validation. The callback also requires `email_verified=true`.
- OAuth state has a five-minute Redis TTL, is consumed with `GETDEL`, and is tied to a short-lived HttpOnly browser binding cookie. Provider requests have explicit request timeouts and a ten-second overall deadline; callbacks return to fixed `/login` or `/knowledge/documents` routes.
- Password login stays enabled. Link and unlink require explicit password reauthentication within five minutes; auth/session transitions are serialized on the singleton Owner row and the live session/CSRF proof is re-read under lock. Google-created sessions do not count as password reauthentication, and password reauthentication is rate-limited.
- Scopes are `openid email profile`. Gmail access remains separate. Login and account linking UI use a user-menu Dialog, with pending, unavailable, and unconfigured provider status states distinguished. Added server-only environment placeholders, provider registration guidance, and [OSS_USED.md](../../OSS_USED.md).

## Contracts

- `GET /api/v1/auth/google/status` → `{configured, linked}`
- `POST /api/v1/auth/google/start` with `{purpose: "login" | "link"}` → `{authorization_url}`
- `GET /api/v1/auth/google/callback` → bounded provider callback and session rotation
- `POST /api/v1/auth/reauthenticate` with `{password}`
- `POST /api/v1/auth/google/unlink`
