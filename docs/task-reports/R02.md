# R02 — Google sign-in and secure owner linking

**Status:** Production code implemented; Next.js build passed; container build is blocked by the Docker Desktop backend startup failure. Sol source review is pending. No live Google credentials are configured.

## Delivered

- Added optional Google OIDC login and account link/unlink endpoints. Google login resolves only the pre-linked issuer + subject identity; it cannot create an owner or link by email.
- Authlib 1.8.0 performs provider discovery, authorization-code exchange, PKCE, nonce, JWKS signature, issuer, audience, and expiry validation. The callback also requires `email_verified=true`.
- OAuth state has a five-minute Redis TTL, is consumed with `GETDEL`, and is tied to a short-lived HttpOnly browser binding cookie. Return paths are fixed allowlisted paths.
- Password login stays enabled. Link and unlink require explicit password reauthentication within five minutes; linking also checks the original session is still live and rotates the BBD-OS session and CSRF cookies.
- Scopes are `openid email profile`. Gmail access remains separate. Added login and Account settings UI, server-only environment placeholders, provider registration guidance, and [OSS_USED.md](../../OSS_USED.md).

## Contracts

- `GET /api/v1/auth/google/status` → `{configured, linked}`
- `POST /api/v1/auth/google/start` with `{purpose: "login" | "link"}` → `{authorization_url}`
- `GET /api/v1/auth/google/callback` → bounded provider callback and session rotation
- `POST /api/v1/auth/reauthenticate` with `{password}`
- `POST /api/v1/auth/google/unlink`
