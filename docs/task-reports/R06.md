## Connector worker finalizers

Connector transactions use `ConnectorObservation`, a detached frozen value captured under source → provisioning → sorted `collector`, `manual_trigger`, and `provider` locks. It compares source ID/generation/status, desired/applied revisions, effective activation state/error/recovery, desired-enabled, credential-presence booleans, and whether header auth is configured. The finalizer flushes domain changes, selects only bounded safe owner scalar values, derives the effective projection, then calls `commit_with_replay` as the terminal suffix. It emits one allowlisted `source.changed` when the observation changes and commits with an empty replay batch for identical/pure bookkeeping state.

Applied finalization at the four inline `drive_activation` error/intent commits and its `begin_enable` outer commit; credential claim stale/dispatch commits; post-HTTP credential failure/acknowledgement commits; workflow blocked/stale/dispatch commits; post-HTTP workflow failure/acknowledgement commits; worker credential delete failure/acknowledgement; and verified unknown-create recovery. Workflow lookup-to-prepared advancement and unknown-create retry scheduling remain plain commits because they only change internal progress/order. The stale-enable workflow branch now commits the prepared cleanup/disabled state before returning `None`. Mutator false results roll back without emitting a replay record.
